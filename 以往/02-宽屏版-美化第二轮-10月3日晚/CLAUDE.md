# 医伴（Yiban）— 项目负责人（主管）工作规则

## 项目目标
「医伴 · 你的私人医生助理」是一个黑客松项目，目标是做出第一代可用的网站：帮患者建档、日常跟踪症状（AI 主动追问并自动记录变化）、就医前生成一页给医生看的病情摘要、就医后把诊断归档、下次复发时调出既往记录。核心价值：患者说不清的，AI 帮着说清楚；患者记不住的，AI 帮着记住。

## 已定决策（人类已逐项拍板，不要擅自更改；要改先问人）
- 技术栈：Next.js 16（App Router，src/ 目录）+ TypeScript + Tailwind 4，`npm run dev` 本地运行，之后可部署 Vercel。
- AI 引擎：智谱 GLM（默认 glm-5），只在服务端 /api 路由里调用，Key 放 .env.local；没有 Key 或接口失败时自动降级为内置规则模拟，演示永远不会挂。
- 界面与 AI 对话全部中文；数据存浏览器 localStorage；单用户、无需登录。
- 视觉：清爽医疗风（白底 + 青蓝主色，圆角卡片，大留白，细线条），要美观、简洁。
- 给医生的摘要：可打印 + 一键复制纯文字（不做分享链接 / 二维码）。
- 主动追问：打开应用时首页按时间出现追问 + 浏览器通知。
- AI 的「基础判断」只做整理与提示（如「建议尽快就医」「与上次情况类似」），不做诊断、不给用药剂量，也不点名可能的疾病。
- 慢病管理（2026-10-02 拍板）：有可用的健康指标、复诊记录和 AI 年度摘要；指标参考范围是一般标准，页面注明个人目标以医生为准。简化后它们的位置见下一条。
- 简化（2026-10-02 拍板「1A 2A 3A」，方案见 docs/简化方案.md）：对患者越简单越好，核心是「快速把我的信息给医生」，信息不减少、操作变简单。
  - 导航只有「今天」和「我的档案」，所有屏幕都是同一个窄列。首页同一时间只突出一件要做的事。
  - 患者只做两种动作：说一句话（打字或语音），或点一个大按钮。不填表，不拖滑杆。轻重用「有点难受 / 比较难受 / 非常难受」。
  - 每天的追问只点「好多了 / 差不多 / 更严重了」，本地立刻反应，不等 AI。新症状每天问，拖了两周以上每周问。
  - 「给医生看」第一屏是大字一眼版，打开就有；细节折叠；年度摘要是其中的「这一年」页签。
  - 「看完医生了」合并了就医结果和复诊记录：拍照、说话或打字，AI 整理后一键存档，之后最多两个问题。看完医生后继续跟踪，直到用户点「我好了」。
  - 少打字三样都做：语音输入、口述存档、拍照存档（glm-asr-2512、glm-4.6v）。只保存整理出的文字，不保存照片和录音。
  - 慢病功能默认收起，打开「我的档案」里的「长期管理」才出现；王秀兰演示自动打开。
  - 字大、按钮大、说人话：正文 17 像素起，要紧的话 20 像素以上，按钮 48 像素以上，不用小灰字；患者界面不出现技术词（只有设置里的「AI 连接」例外）。
  - 不替用户编数字：没说过的轻重、体温、用药情况不写。危险信号由本地规则判断，不依赖模型。
- 模拟用户迭代（2026-10-02 人要求）：用模拟用户实际试用来驱动迭代，轮数和人数由主管定，每轮的发现和改动记进 PROGRESS.md；砍功能、改主流程这类大改动先发给对接员请人拍板。
- 两套演示并存：李明（急性症状）和王秀兰（糖尿病 12 个月），直达链接是 /demo/liming 和 /demo/wang。王秀兰的时间轴以今天为第 12 个月，第 7 个月是五一假期。演示患者均为虚构。
- 不要静默替换人自己建的档案：演示链接遇到自建档案会先询问，只有带 ?replace=1 才直接替换。

## 角色与协作方式
- 本会话是「主管」：负责写代码、做技术决定、跑构建和测试。
- 另有一个「对接员」会话（规则见 LIAISON.md）专门和人沟通。人类的消息会以「[对接员] 事件：结论」格式发来，当作用户的决策直接执行；需要澄清时回消息给对接员，由它去问人。
- 需要人做的事（填 Key、拍板、提供素材、试用反馈）：写进 HUMAN_TODO.md，并用 SendMessage 发给对接员，一条消息只说一件事。
- 每完成一个阶段，在 PROGRESS.md 追加一行（带日期），对接员靠它回答进度。
- 人类交来的材料在 inbox/ 里，对接员会在消息里写明文件名。

## 工程约定
- 不 commit、不 push，除非人类明确要求。
- 任何 Key 只存在 .env.local，不写进代码、文档或聊天记录。
- 改动后跑 `npx tsc --noEmit`、`npm run lint`、`npm run test:unit`；改了规则引擎再跑 `npm run test:rules`（需要先在 3001 端口起一个不带 Key 的服务）；UI 改动要在浏览器里看一眼再交付。
- 浏览器验证和模拟用户都在单独的端口上跑（3100 以上），不要动 http://localhost:3000 里人自己的数据。
- 生产构建和 `next start` 的测试服务共用 .next 目录：有模拟用户在跑的时候不要重新构建。
- 可信优先于文采（三轮模拟用户的共同结论，改动前先看 PROGRESS.md）：给医生看的第一屏和时间线只由记录按规则生成；是否提示就医、危险信号、复测跟进都由 src/lib/ai/fallback.ts 和 src/lib/metrics.ts 里的规则决定；模型输出一律经过 src/lib/ai/normalize.ts 的过滤（没说过的否定句、猜原因、重复提问、笼统答案）。新增提示词之外，优先把约束写成代码和测试。
- 未定的问题先给选项让人选，不要猜。
