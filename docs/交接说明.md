# 医伴 · 患者版（VisitSmoothie）交接说明

写给接手的队友。更新于 2026-10-03（美化第二轮之后）。

## 1. 怎么跑起来

需要 Node.js 20.9 以上。

```bash
npm install
npm run dev          # 打开 http://localhost:3000
```

- AI 用智谱 GLM，Key 放在项目根目录的 `.env.local`（变量名见 `.env.example`）。没有 Key 也能跑：对话、整理、摘要会自动改用内置规则，只是不能听语音、认照片。
- Key 只在服务端 `src/app/api/**` 里读，不会进浏览器。
- 检查命令：`npx tsc --noEmit`、`npm run lint`、`npm run test:unit`（1485 项，全部应该通过）、`npm run build`。

## 2. 三个入口最快看完整个产品

| 想看什么 | 怎么做 |
|---|---|
| 一个有完整记录的病人 | 打开 `/demo/lin`，不用密码，直接进入虚构病人「林叔」的账号 |
| 注册和登录流程 | 打开 `/welcome`，点「开始我的健康旅程」注册，或「已有账号？登录」 |
| 跳过所有必填，一路往下点 | 点每页左下角（手机上在页面顶部）的「开发者：关」，变成黄色「开发者：开」。开着时注册七项和密码都可以不填，登录可以不输密码。再点一下关掉。默认关，只记在这台浏览器里 |

### 林叔演示

照队友的剧本《虚构患者资料_中英双语》做的：46 岁男，自述高血压但药名剂量待核对，父亲高血压、母亲 2 型糖尿病，吃虾起风团。档案里有 5 月 12 日一次左膝不适（没有明确诊断），以及这次左膝内侧酸痛的问诊、骨科医嘱（原因待查，不加药，不做检查，一周后复诊）和两个提醒（复诊前一晚 20:00 准备病历和药盒、复诊当天 8:30 复诊准备）。日期以打开演示的那一天为「看病那天」。每次打开链接都会重新载入演示数据，不影响别人的账号。

## 4. 设计规范

苹果官网和 iOS「健康」的路子：一个主色、近白底、1 像素细线、有层次的卡片、克制的动效。

- **颜色、阴影、圆角**：`src/app/globals.css` 顶部的 `@theme`。主色是 Visit Smoothie 的 `#167493`（`brand-600`），字标深墨色 `#173f4f`。
- **字号**（`globals.css` 里的类）：`t-display` 页面标题和大字，`t-title` 卡片或屏幕标题，`t-heading` 卡片里的小节，`t-lead` 一句要紧的话，`t-body` 正文，`t-number` 大号数字。
- **材质**：`material`（从上往下有一点光感的卡片）、`material-raised`（最重要的那张卡）、`glass`（毛玻璃，只用在输入栏、提示这类浮在上面的东西）。
- **图标**：只用 lucide，放在 `IconTile` 里（`tile-brand`、`tile-ink`、`tile-danger` 等光面方块）。
- **动效**：`press`（按下的反馈）、`skeleton`（加载中的骨架）、进场和渐显动画。系统设置了「减少动态效果」时全部关掉。
- **公共组件**：`src/components/ui.tsx`，有 Button、LinkButton、Card、IconTile、RowLink、Field、Input、Select、Toggle、Segmented、Modal、PageTitle、Spinner、Skeleton、Stat、Notice 等。新页面先用这些，别自己再写一套。
- **字标**：`wordmark` 和 `wordmark-mark` 两个类，衬线体加「v.」标志。
- **硬规矩**（用户里有老人）：正文至少 17 像素，要紧的话至少 20 像素，能点的地方至少 48 像素高，文字和底色对比度至少 4.5:1，患者界面不出现技术词。
- 电脑和手机（约 390 像素宽）都要看一眼，手机上不能左右滑。

## 5. 产品上的规矩

- AI 只做整理、提示和初步分诊（要不要看医生、多急、挂哪科），不做诊断，不点名可能的疾病。
- 用药：不替人定剂量，不改医嘱。可以复述医生开的，也可以讲说明书上的一般用法，并说明以说明书和医生为准；剂量数字只复述医嘱。
- 可信优先于文采：给医生看的第一屏和时间线只按记录用规则生成；要不要就医、危险信号由本地规则判断（`src/lib/ai/fallback.ts`、`src/lib/metrics.ts`），不靠模型；模型说的每一句都过 `src/lib/ai/normalize.ts` 的过滤。想加约束，优先写成代码和测试，不只是改提示词。
- 不替用户编数字：用户没说过的轻重、体温、用药，一律不写。
- 所有病人都是虚构的。

## 6. 现在有什么

- 注册、登录、退出登录（照队友 codex/visit-smoothie-onboarding 的界面和流程）；账号存在浏览器里，每个账号的记录分开存，密码只存加盐哈希。
- 林叔演示（`/demo/lin`）和开发者开关。
- 看医生之前：对话问诊，一次问一个问题，问清八类信息；疼痛可以在身体图上点；口语先确认再写成医生的说法，原话保留；和以前的记录或以往病史有关时问「这次和那次比，哪里一样、哪里不一样」；问完生成病情描述和就医建议（要不要看医生、挂哪科）。可以打字、语音、拍照。
- 看完医生：录音（最长 60 分钟）或拍病历、处方，整理出诊断、药、注意事项、复诊，存进就诊记录，放进首页提醒（复诊前一晚提醒准备要带的东西）；可以追问解释。
- 首页 to do & tips：提醒可开关，应用开着时到点提醒并弹浏览器通知；问题框可以问自己记录里的事。
- 就诊记录和给医生看：第一屏大字一眼版，细节折叠，可以打印、存 PDF、复制文字。
- 我的档案：七项资料、补充以往病史、修改；设置（提醒、备份、AI 连接测试）。
- 应急手册：按档案拼出急救步骤和要给急救人员看的信息。
- 长期管理（慢病）：健康指标和「这一年」，默认收起，在「我的档案」里打开。
- 界面可以切英文（只翻了固定文字，AI 回答仍是中文）。
- 美化第二轮：所有界面按上面的设计规范做过，电脑和手机的截图在 `docs/美化截图-第二轮/`。

## 7. 还没有、或者已知的问题

- 账号只存在这台电脑的浏览器里，不是真正的安全措施；换浏览器或电脑就没有数据，也没有云同步。
- 复诊当天的提醒固定在 9:00，没有读医嘱上写的具体钟点；医嘱里的「本次未开具检查」没有单独显示。
- 在应用里点「回首页」离开时不拦未保存的病情描述，下次回到对话才问「保存、放弃，还是接着改」。
- 英文只翻了固定文字，AI 回答和安全规则还是中文；现在的布局里切换中英文的按钮只在应急页。
- 真实的长录音、真实拍照、浏览器通知授权没有经过真人试用，只用合成数据验证过。
- 应急手册的急救文字是通用常识，正式给真人用之前要请懂医的人审（`src/lib/sos.ts`）。断网时重新打开应急页会打不开。
- 手机用局域网地址打开时浏览器不让用麦克风；部署到 https 地址后才行。还没有部署。
- 体检报告建档只支持照片（最多 6 张），不支持直接传 PDF。
- 没有自己的 404 页；紧急联系人还不能一点就拨号。
- 李明、王秀兰两套旧演示只留在 `scripts/fixtures/` 给单元检查用，应用里没有入口。

## 8. 协作约定

- 改完跑 `npx tsc --noEmit`、`npm run lint`、`npm run test:unit`，界面改动在浏览器里电脑和手机各看一眼。
- 不要把 Key 写进代码或文档。
- 新功能尽量配单元检查，放在 `scripts/tests/*.test.ts`（用 `scripts/tests/_check.ts`）。
