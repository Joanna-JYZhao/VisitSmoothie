## 人提供的功能说明（原文）

1.问诊部分
首先需要一个页面来问用户哪里不适，用户给一个回答。
需要chatbox问用户他们缺少的信息，般来说问诊需要的信息种类包含（伴随症状 不舒服的部位 疼痛方式 持续时间 病史 接触药物 什么时候会不舒服 有没有特定情境或时间)
如果是疼痛 例如膝盖 需要具体位置问讯 可以借助图片来帮助患者清晰自己是哪里疼痛 可以和医生更好的表述。
如果是判断为慢性病 则使用引导性提问和以往使用这个项目的以往的report来整合病史。或者以往有记录就可以直接调用放在描述里
用户如果说了一些口语化 不正式 不方便医生理解的词 就通过提问和描述帮助其确认更正式的描述（比如扭着疼，可以形容为绞痛）
如果是有关联的东西被识别到 比如以往有一些信息和当前描述有医学关联 就进行追问确认 避免患者感觉很轻度 不表述出来 遗漏重要信息
最后在信息完全 好理解的时候为用户生成一段话 作为病情描述。
如果用户不满意 则反馈给chatbox 纠正某一个部分 或者用户提出疑问和需要添加的部分 重新生成

2.在就医后的部分 也就是医嘱部分。
医嘱的图片是input，有一个上传的地方。
后台需要提取当中的信息，包括有哪些药物 需要注意的事项（需要关注什么） 病症诊断 时间和地点 还有其他治疗措施（例如锻炼哪里 或者制动）复诊时间（可以有可以没）
首先把整理完的信息展示给用户
通过选择模块来帮助患者（a整理需要做什么 并在产品内设置提醒 发送通知来提示。b需要解释，例如原理和副作用）
选择完成后
如果是a则整理出来待办 告知用户 用户可以在提醒被设置之前选择提醒频率 哪些需要哪些不需要提醒 然后设置 执行
b则让用户说是哪个部分是需要解释的 引导提问（比如可以列出不同的各部分 怎么解释的方法）
有复诊的话则协助用户下次复诊可以说什么 后续有副作用出现都可以在这个记录里继续进行交互记录。

1和2部分都会存档在用户的个人就诊记录里 可以是一次完整的就医记录 也可以是分开的（只有1或只有2的一次记录）
在用户完成后离开页面弹出提示问它需要保存还是放弃这个记录

*用户的个人信息
注册的时候需要包含 年龄，性别，学历，基础病，家族遗传病（基础病这部分可以跳过后续再填）
可以在存储的report的地方自主增加以往病史 用于在问诊的时候有可能需要添加的部分。
