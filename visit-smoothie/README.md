# Visit Smoothie

仅包含欢迎页、首次注册、姓名/密码登录、个人资料与退出登录。原 Health Journal 的记录、就诊、AI、摘要、导出、示例和偏好功能已移除。

## 启动

需要 Node.js 24+，无第三方依赖。

```sh
cd visit-smoothie
./start.sh
```

也可直接运行 `node server.mjs`。打开 <http://127.0.0.1:4190/#register>；用 `PORT` 更改端口。启动脚本优先使用本机 Codex Node，再回退到 PATH；可通过 `SMOOTHIE_NODE` 指定运行时。

## 注册与登录

- 昵称用于系统内展示，支持 1–60 个字符，可在个人资料中修改，也可与其他人重复。已有账号未填写昵称时，默认展示原姓名。
- 姓名作为登录用户名；重复姓名需使用能区分的姓名。大小写、全角字符和多余空格规范化后检查唯一性。本版登录姓名不可修改，修改昵称不影响账号或登录。
- 基本信息必填：昵称、完整出生日期、性别、学历。登录账号单独填写姓名、密码及确认密码。年龄按生日自动计算，不单独存储。
- 选填：基础病、家族遗传病、过敏史；支持多行，登录后可继续补充。
- 密码为 15–128 个字符。密码经随机盐 scrypt 哈希保存，数据库不存明文密码。
- 每个账号分配独立 UUID；所有资料读写由服务端会话选定账号。会话最长七天，退出即撤销。
- 编辑冲突会提示刷新，保留当前草稿；浏览器刷新会丢弃未保存草稿。密码不会保存在表单草稿或浏览器存储中。

浏览器需要支持 Web Locks，认证操作使用它协调多标签页登录/退出。数据保存在此服务的 SQLite 数据库中；换浏览器仍需连接同一服务并登录同一账号。此版本只监听本机回环地址，尚未部署为公网服务，未提供找回密码流程。

## 数据

默认数据库为 `visit-smoothie/.data/accounts.sqlite`，可通过 `SMOOTHIE_DB` 指定其他位置。数据库目录被 Git 忽略。备份前应停止服务，或使用 SQLite 备份机制。

原 `health-journal/.data/` 下已有的本地数据保留在磁盘上，由根目录 `.gitignore` 排除；新应用不读取、不迁移、不提供访问这些数据的接口。原应用代码可以从 Git 历史恢复。
