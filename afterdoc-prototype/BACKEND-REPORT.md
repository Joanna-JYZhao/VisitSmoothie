# AfterDoc backend handoff

Implemented the local Node backend in `server.mjs` and `server/*`, with `package.json` and executable `start.sh`. It binds to `127.0.0.1:4173` by default (`PORT` overrides), serves only `public/`, and provides the health, agent, and document extraction endpoints specified in `BACKEND-BRIEF.md`. It reads the authorized parent `.env` without logging or copying the key. No uploads or patient state are persisted.

DeepSeek's current official docs confirm `deepseek-flash`, `https://api.deepseek.com`, JSON mode with `response_format: {type:"json_object"}`, and non-thinking mode with `thinking:{type:"disabled"}`: https://api-docs.deepseek.com/quick_start/pricing/ , https://api-docs.deepseek.com/guides/json_mode/ , https://api-docs.deepseek.com/guides/thinking_mode/ .

The localhost/Vision tests required the approved sandbox escalation.
- Authorized tiny synthetic DeepSeek request: success, model `deepseek-flash`, approximately 1.1 seconds. The first sandboxed network attempt was blocked; the approved network run succeeded.
- Synthetic end-to-end model checks: plan extraction produced two source-linked items; intake produced a follow-up; plan Q&A returned a validated citation; understanding check returned `matched` with a validated citation after normalizing the model's `sourceQuote` alias. These checks used invented Medicine A text only.
- A synthetic record-only DeepSeek intake returned three facts cited to the record's exact id, with `ready:false`. No real patient text was used.
- The full fictional Chinese demo record in `public/fixtures.js` produced six verified plan items: two medications, one test, one follow-up, and two instructions. The test item retained only the clinically relevant missing preparation requirement (`具体检查前准备要求`); medication items had no missing fields. The symptom-recording item stayed an instruction even though its source mentions follow-up.

Limits: Scanned PDFs return a readable-text error; image OCR applies to image uploads, not PDFs. OCR can misread clinical text, so the patient must review and edit it before plan extraction. Automated quote checks prove exact source matches and prevent unsupported clinical field strings from being accepted; semantic truth of model-written summaries and explanations cannot be fully proven mechanically. Model or network failures are reported as errors rather than replaced with fake answers.

Integration note: `validatePlan(raw, documents, language = 'en')` now localizes complexity reasons for `zh`. The server passes the request language. Warnings are returned only when the warning string is an exact substring of a source document. `clinical_review` and `source_missing` routes use fixed boundary replies, even if the model supplied an instruction. The already-running parent-owned server must be restarted by its owner to load these edits.

Intake accepts optional `payload.records:[{id,title,text}]`, with an empty array allowed; each record may contain up to 30,000 characters within the overall 256 KB JSON request limit. Fact results include `sourceId:'patient'` or an exact record id, verified against the matching source; old model facts without `sourceId` infer patient first, then records. A message with `kind:'record'` does not count toward the six clarification turns. The frontend should keep `payload.turn` as the number of actual clarification turns. Once ready or `finish:true`, the backend clears the question and options and supplies a brief summary-ready reply. Medication items with empty dose, frequency, or duration are marked missing. The DeepSeek timeout now covers both response headers and body parsing.

Plan extraction now normalizes known model kind aliases such as `follow_up` and `follow-up`; an explicit `instruction` is preserved. Unknown kinds fall back from strong title wording only. `missing` excludes rationale, explanation, summary, and medication-only fields on tests and follow-ups. A test quote explicitly stating preparation instructions are absent produces a preparation missing item even if the model omits it. The extraction prompt now gives an exact-kind JSON example and asks for actionable missing directions only.

Local photo OCR: `POST /api/extract-document` accepts PNG, JPEG, WebP, HEIC, and HEIF images. PNG, JPEG, WebP, and HEIC were verified using fictional label images; HEIF uses the same ImageIO path but was not separately tested. The existing `document` response gains `extraction:'ocr'` and `requiresReview:true`; the frontend should require explicit patient review/edit of `text` before calling `extract_plan`. OCR uses macOS Vision with `zh-Hans` and `en-US`, accurate recognition, ImageIO orientation metadata, and no external image API. The Swift helper compiles into ignored `.runtime/` and is reused until its source changes. Temporary uploaded image files use a private OS temp directory and are removed after each request; the compiler and OCR child processes receive a minimal environment without the API key. Cold compilation was about 28 seconds in this environment; cached OCR took under a second on the synthetic fixture. Invalid, blank, oversized, and timed-out images return clean errors. Local Vision framework access was blocked by the standard sandbox (`nilError`), but the same synthetic images passed with approved host access. No running server process was changed.
